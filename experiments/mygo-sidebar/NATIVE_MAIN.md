当前 `-native-main` 已切换为按正式界面对齐的 1120 × 800 主窗口，新增备注、全部筛选、固定操作、设置分区、三主题和独立快速添加。**仍未达到完整 UI / 业务等价**；当前实现与剩余差异以 [UI 对齐记录](UI_PARITY.md)为准。下文内存比较及 19 项测试 / Computer Use 流程属于旧的 760 × 600 简化渲染器，不能当作当前版本结果。当前构建执行 105 项顶层测试和 vet；第二批补上删除、完成撤销、稍后与位置 / 密度控制，第三批补上日期时间、macOS 系统提醒和临时任务清理，第四批补上排序与 +N 溢出列表，第五批补上独立资料的保存与重启恢复，第六批补上安静模式、启动偏好与 Dock / 默认值设置，第七批补上 JSON / CSV 导出，第八批补上快速添加的时间识别、全局快捷键与焦点恢复，第九批补上 macOS 登录启动、实际系统状态与失败补偿，第十批校准内容区尺寸、三主题布局与空列表入口，第十一批补中文日期控件与实际卡片排版测量，第十二批补分段日期输入、焦点 / 基线校准与标题展开动画，见 [本轮记录](SEGMENTED_UI.md)。

## 运行

```bash
bash experiments/mygo-sidebar/build-macos.sh
mkdir -p build/results/mygo-native-main-manual
open -n build/bin/mygo-lab/SideletMyGoLab.app --args \
  -native-main -main \
  -output "$PWD/build/results/mygo-native-main-manual" \
  -log-file "$PWD/build/results/mygo-native-main-manual/app.log"
```

先退出其他实验实例。`-native-main` 和 `-hybrid` 互斥；两者均可结合 `-main-hidden` 启动时只显示侧栏。`⌘1` 打开 / 重开主窗口，`⌘E` 编辑当前卡片，`⌘Q` 退出实验。关闭主窗口后侧栏继续运行；重开创建新窗口并恢复上次位置，已提交任务保留，未保存草稿清空。默认按保存的启动偏好显示主窗口，首次手动创建资料仍打开，登录启动则遵循偏好；上例使用 `-main` 强制显示。

## 功能与实现

- 新增任务、行内编辑标题 / 三档重要程度（普通、重要、紧急）、取消编辑、完成、恢复、待办 / 已完成切换、打开原生卡片。
- 最小窗口尺寸下列表可以滚动。输入控件使用稳定任务 ID 与父节点 key，其他任务变化和窗口缩放不重新创建正在编辑的字段；重复编辑显式恢复标题焦点。
- 使用混合原型已有的 `TasksService`，主线程串行操作同一份 Go 模型。原生主窗口不绑定 Web 服务、不设置 Web 前端、不发布 Web 事件；任务变化只通知自身视图刷新。
- 主窗口和卡片均按任务 version 保存。另一端更新后，过期提交被拒绝，提示重新编辑，并保留草稿。正在编辑的任务被完成或恢复到另一列表时结束该编辑。
- 卡片保存 / 取消后恢复原来窗口与输入焦点，沿用已有 macOS 输入适配。原生主窗口也可作为同一应用的普通窗口回退目标。

当前默认使用独立持久资料，首次为空任务列表；`-memory` 可恢复三条合成内存任务的历史运行方式。侧栏直接显示最多八项并随主屏可用高度预留 +N，更多固定任务可从溢出卡片访问；未固定任务不占显示位置。已提交任务、排序、主题、布局和提醒回执重启恢复；原生界面已接入 macOS 提醒与通知设置。独立 JSON 资料没有 SQLite 迁移或导入正式任务，已接入安静模式、启动窗口偏好、默认值保存和 Dock 显示；JSON / CSV 导出已接入；macOS 登录启动已接入；系统状态见 [登录启动记录](LOGIN_STARTUP.md)，资料隔离见 [持久化记录](PERSISTENCE.md)。这里历史记录中的“同功能”指与独立 Web 任务主窗口相同的基础任务操作，不代表与正式应用全部功能等价。

## 历史简化界面验证

19 项 Go 测试、`go vet`、`go test -race` 通过。新增四项原生主窗口测试覆盖输入与重要程度、中文组合输入 / 焦点 / 缩放、过期草稿保护、完成与恢复、共享卡片和最小窗口滚动。Windows amd64 / arm64 交叉编译通过，尚无 Windows 实机结论。

已有十阶段 AppKit 诊断全部通过：只检查自有窗口的透明区域、焦点与生命周期，不注入系统输入，也不代替正常输入面板的硬件鼠标路由验收。

Computer Use 在正常输入适配模式下验证主窗口和卡片：系统拼音新增“你”并选择紧急，主窗口改名为“世界”并选择重要，再编辑“测试”取消后原任务保持“世界”；卡片保存“测试”后主窗口立即更新。主窗口字段输入“你”，快捷编辑卡片并取消后，无需点击继续输入“好”，得到“你好”；保存也恢复同一字段。完成任务隐藏卡片并压紧侧栏，恢复后标记重新出现。关闭主窗口 ID 2 后重开 ID 4（中间 ID 3 为卡片），四项任务与已提交修改保留。

UI / 日志证据位于 `build/results/mygo-native-main-20261007/ui/`；诊断位于 `native-check/native-check.json`。界面截图为 `ui/native-main.png`。本轮没有全面验收多屏、Spaces、正常面板持续拖动及长时间输入法候选交互；跨应用焦点恢复的历史验证见 [混合原型记录](HYBRID.md)。

## 同功能内存对比（历史简化界面）

使用同一 macOS 二进制，分别经 Launch Services 启动干净的 `-native-main` 和 `-hybrid` 进程。正式 Sidelet 保持运行，采样只汇总实验根进程及同时匹配 resource / jetsam coalition 的 WebKit。正常输入适配，不启用输入追踪或直接输入测试入口，不强制 GC、不结束 WebKit、不在采样时抓取截图。

两种模式均为 760 × 600 主窗口、同样三条任务和默认重要程度。先采样刚打开的主窗口，再执行相同流程：打开第一条卡片 → `⌘E` 编辑 → 系统拼音输入“你” → 取消 → 主窗口完成第一条 → 已完成页恢复 → 返回待办。任务内容保持相同，第一条 version 变为 3，卡片已隐藏。随后采样操作后主窗口打开和主窗口关闭状态。

每段等待三秒后采样十五秒，每五秒一次，共四点。原始 CSV、逐进程 JSONL、环境和二进制哈希保留于 `build/results/mygo-native-main-20261007/memory/`。

| 状态（中位数） | 原生 RSS / footprint | Web RSS / footprint | 原生进程 / Web 进程 |
| --- | ---: | ---: | ---: |
| 主窗口打开，尚未打开卡片 | 121.85 / 44.59 MiB | 206.94 / 70.16 MiB | 1 / 4 |
| 相同操作后，主窗口打开、卡片隐藏 | 129.56 / 46.00 MiB | 225.65 / 78.44 MiB | 1 / 4 |
| 操作后关闭主窗口 | 122.89 / 39.28 MiB | 186.77 / 57.72 MiB | 1 / 3 |

操作后的比较较稳定：原生少 96.09 MiB RSS（42.58%）和 32.44 MiB footprint（41.36%）。原生初始段 RSS 范围为 115.31–128.53 MiB、footprint 为 38.05–51.28 MiB；该段发生内存回落，中位数不能代表固定基线。操作后原生四点均为 129.56 / 46.00 MiB；Web 为 RSS 225.56–225.66 MiB、footprint 78.35–78.53 MiB。

这次 Web 关闭状态的四点都没有 WebContent，GPU / Networking 仍在，内存有部分回落；此前混合原型短测曾观察到 WebContent 保留，因此“关闭后一定不释放”和“关闭后完全卸载 WebKit”都不符合现有证据。原生关闭主窗口也没有回到从未创建主窗口的旧版侧栏基线。

一核平均 CPU：原生初始 / 操作后 / 关闭分别为 0.2774% / 0.0035% / 0.0031%，Web 为 0.0352% / 0.0489% / 0.0089%。初始段包含绘制和回收波动，短测不用于断言哪一种整体更省电。

采样原生 PID 92971、Web PID 94600。六段二进制哈希相同：`85b9a207a3d4a7854a306f629e416cbf3552ee85c6ebfc24ed3661a391dcef18`。日志中的操作后完整任务快照（含 ID、标题、备注、重要程度、完成状态、version 与 revision）逐项一致。汇总在 `build/results/mygo-native-main-20261007/summary.json`。

短测只反映这些任务操作和窗口状态，存在 Go 堆回收、原生绘制缓存与 WebKit 缓存波动。不能推导正式应用迁移后的固定内存占用，也不足以判断长期稳定性、耗电或 Windows 内存。

现阶段继续以正式完整 UI 为准推进，剩余界面状态和共享业务接入顺序见 [UI 对齐记录](UI_PARITY.md)。跨平台迁移前仍需 Windows 实机检查中文输入、透明窗口和多屏。历史数据支持继续探索全原生，但没有据此迁移正式应用。
