# Web 主窗口与原生侧栏混合原型

2026-10-07。本原型使用一个 MyGo 应用事件循环：任务主窗口加载内嵌 HTML / CSS / JS，常驻侧栏和浮动卡片由 Go 原生绘制。没有把两个框架的事件循环嵌套运行，也没有替换正式 Sidelet 的 Wails 宿主。

后续已增加不创建 WebView 的原生任务主窗口；与此模式相同任务操作的新版内存对比见 [原生主窗口记录](NATIVE_MAIN.md)。本文后面的采样保留为当时版本的历史结果。

## 运行

```bash
bash experiments/mygo-sidebar/build-macos.sh
mkdir -p build/results/mygo-hybrid-manual
open -n build/bin/mygo-lab/SideletMyGoLab.app --args \
  -hybrid \
  -output "$PWD/build/results/mygo-hybrid-manual" \
  -log-file "$PWD/build/results/mygo-hybrid-manual/app.log"
```

关闭其他实验实例后启动。`-hybrid -main-hidden` 只启动原生侧栏，尚不创建 WebView。菜单 File → 打开任务窗口，或 `⌘1`，打开 / 重开任务窗口；File → 编辑当前卡片，或 `⌘E`，编辑已打开的卡片。主窗口关闭时走 MyGo 的窗口关闭 / 原生资源清理路径，并清除主窗口引用；再打开创建新窗口，任务状态从 Go 重新读取。窗口关闭不保证 WebKit 进程立即退出，见后文实测。关闭主窗口不退出原型；`⌘Q` 退出。

任务新增、标题 / 重要程度编辑、完成、恢复和打开卡片均使用同一份合成任务。三种重要程度为普通、重要、紧急。待办最多八条，并根据主屏可用高度缩减；已完成任务不会占侧栏位置，完成后可以继续添加。该限制用于限定实验窗口，不是正式版的业务方案。所有任务只在本次进程运行中保留，退出后重置；不读写正式数据库。

## 数据与生命周期

- Web 通过 MyGo 的服务绑定调用 `TasksService`。所有读写排入主线程，和原生控件共享相同模型，不依靠轮询，也不复制出第二份任务存储。
- 任务 ID 保持稳定，完成后只压紧侧栏布局；新增 / 完成同步调整原生窗口高度和输入区域。
- 原生保存 / 完成发布 `lab:tasks-changed`，Web 服务的操作同样发布快照；事件携带递增 revision，页面忽略较旧响应。
- 每条任务携带 version。Web 编辑提交预期版本，原生编辑保存开始时的版本。过期草稿显示冲突提示，保留当前任务和草稿，不能覆盖另一窗口的新内容。
- Web 事件更新保留正在编辑的 DOM，避免无关任务变化打断输入法组合。页面只使用内嵌资源，依赖现有 MyGo 注入的 `window.mygo`，没有新增 npm 包、外部脚本或远程服务。
- 保存 / 取消后恢复原应用；来源是同一应用的普通窗口时恢复那个窗口。辅助功能客户端显式抬高侧栏 / 卡片时，混合模式回到可见的 Web 主窗口。用户主动切到其他应用时，结束编辑不把焦点拉回来。

实现依据固定版本的 [MyGo 服务绑定](https://raw.githubusercontent.com/egoist/mygo/v0.2.16/docs/bindings.md) 和仓库中同版本的 frontend / windows 文档。Web 服务会并发调用，主线程串行读写是本原型为原生模型选择的实现方式。

## 验证

15 项 Go 测试、`go vet` 和 `go test -race` 通过。新增测试覆盖 Web / 原生共享任务、两端过期草稿拒绝、稳定 ID 与侧栏压紧、无效输入、编辑期间打开另一卡片不会丢草稿、并发调用和完成后释放容量。最终源码通过 Windows amd64 / arm64 交叉编译；没有 Windows 实机结论。

正常 macOS 非激活输入面板的十阶段 AppKit 诊断通过，包括透明空白、后台 tracking、编辑 / 取消 / 连续编辑、移动、完成与释放。报告在 `build/results/mygo-hybrid-20261007/native-check/native-check.json`。

Computer Use 实机记录：

| 原生保存 | 系统拼音输入“你好” / “世界”，Web 列表立即显示相同标题 |

## 内存与后续判定

内存使用现有 `scripts/profile-macos.py` 汇总根进程以及同时匹配 resource / jetsam coalition 的 WebKit。通过 Launch Services 单独启动，正式 Sidelet 仍在运行，未混入实验 coalition。采样不强制 GC、不停止 WebKit、不抓取截图。

同一最终二进制、同一进程 PID 81643、同一三条初始任务、正常非激活输入面板模式；每个状态采样 15 秒 / 每 5 秒一次，共四点，取中位数。打开和关闭后各等待三秒才开始采样；关闭后三秒到十八秒是本次关闭状态的观察窗口。

| 状态 | 汇总 RSS | 汇总 footprint | 进程数 / WebContent |
| --- | ---: | ---: | ---: |
| 冷启动，尚未创建主窗口 | 96.36 MiB | 23.45 MiB | 1 / 0 |
| Web 主窗口打开 | 212.56 MiB | 73.42 MiB | 4 / 1 |
| 主窗口关闭后 | 213.59 MiB | 80.00 MiB | 4 / 1 |

各段内存和进程集合稳定；一核平均 CPU 分别约 0.0176%、0.0907%、0.2866%。短测不足以判断长期稳定性或耗电。

**关闭后未观察到明显内存回落，也没有回到冷启动纯原生水平。** 初次 WebContent PID 82188 在关闭后仍存在；重开时由 83791 替换，第二次重开由 84232 替换，两次重开后的集合仍只有一个 WebContent。MyGo v0.2.16 的 `internal/darwin/window.go:cleanup` 会移除消息处理器 / 观察者、停止加载、清除委托及释放 WebView 等对象；本实验没有绕开它、手动杀进程或使用 WebKit 私有终止接口。

进程替换且未叠加的现象与 WebKit 保留可复用进程资源相符，但这只是当前证据下的推断，不是对 WebView 对象最终释放的证明，也不是长期无泄漏结论。本轮不把“关闭窗口”当作“已卸载 Web 引擎”的同义词。

原始 CSV、逐进程 JSONL、环境 / 哈希、摘要和重开记录都在 `build/results/mygo-hybrid-20261007/memory/`。采样二进制 SHA-256：`52ffb674d6b78fdcd176b8ddb09ee7c449d07ef7244963db9a9150bd3aabb695`。其冷启动仅侧栏的表现很好，但原型不包含正式版的 SQLite、提醒、设置、主题和完整任务界面，不能据此承诺正式版迁移的内存收益。

下一步先区分关闭后的 WebKit 缓存与实际 WebView 引用保留，再评估是否需要让 Web 主窗口在独立进程中运行。跨屏 / DPI / Spaces、正常输入面板中的持续硬件拖动及 Windows 实机仍保留为后续验收，正式 Wails 应用暂不迁移。
