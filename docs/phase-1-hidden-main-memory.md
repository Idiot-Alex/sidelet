# macOS 主窗口隐藏视口优化 · 构建 11

2026-10-06，Apple M3 Max / macOS 26.6.2。构建 11 已安装到 `/Applications/Sidelet.app`。证据目录：`build/results/build10-hidden-main-trial-20261006/`，不进入 Git；目录沿用构建 10 对照试验名称，最终发布为构建 11。

## 实现和保留依据

隐藏主窗口时，前端先保存滚动位置和焦点、收起整个页面绘制内容，组件及未保存草稿继续挂载。Svelte 更新后确认隐藏状态，控制器才把原生 WebView 缩为 1×1；NSWindow 的大小和位置保持原值。重开时先恢复 WebView 尺寸和自动调整标记，再恢复页面布局、滚动与焦点，收到对应版本的布局确认后显示原生窗口。

控制器与前端使用版本号拒绝旧回复；已经处理的显示确认不会再次抢焦点。窗口加载完成前请求隐藏也会同步隐藏状态。重新聚焦已经可见的窗口不会恢复旧滚动位置；切换任务 / 设置页时沿用原有页面回到顶部的行为。原生函数只处理隐藏窗口中唯一的 WKWebView，缺失或多个 WebView 时不尝试缩小，避免误动其他内容。

该机制应用于 macOS 主窗口的隐藏按钮和窗口关闭路径。没有销毁 WebView、关闭 WebContent 进程、强制 GC 或增加普通模式轮询。Quick Add、Quick Card 及侧栏不使用此机制。Cmd+H、最小化、多屏 / Spaces / 休眠等路径尚未补充实机结论，Windows 保留原来的主窗口行为。

## 撤回的单独页面收起试验

首先只收起前端页面，没有缩小 WebView。原版隐藏后的 RSS / footprint 为 286.1 / 152.5 MiB，试验为 295.9 / 152.4 MiB，整体无明确收益，不作为独立优化保留。

随后加入隐藏视口缩小。首次打开并隐藏的同流程试验为 284.6 / 136.2 MiB，footprint 减少约 16.3 MiB；主窗口 WebContent 从 76.6 降到 59.2 MiB。普通采样结束后才运行 vmmap，原版主窗口图形资源 dirty 约 52.0 MiB，视口原型约 34.2 MiB。该图形分类属于原型佐证，最终收益采用下面的最终构建实测。

原型源码和二进制单独保存在证据目录，不用它们代替发布版验收。

## 最终构建普通模式同流程对照

两版均使用相同 13 条合成任务、两条固定、相同设置及独立资料目录。启动时只有侧栏，然后打开主窗口、填写未保存标题、滚动一页、关闭、重开、设置页往返两次，最后关闭主窗口。所有 UI 操作完成后等待 15 秒，采样 30 秒，间隔 5 秒，共 7 点。没有打开 Quick Add / Quick Card，没有启用内存诊断、指针追踪或交互 fixture。

| 项目 | 构建 10 | 构建 11 |
| --- | ---: | ---: |
| 总 RSS 中位数 | 303.5 MiB | 308.7 MiB |
| 总 footprint 中位数 | 159.9 MiB | 141.0 MiB |
| 主窗口 WebContent footprint | 78.0 MiB | 60.8 MiB |

| 进程 / WebContent | 5 / 2 | 5 / 2 |

整体 footprint 减少 **18.94 MiB（约 11.8%）**，主窗口 WebContent 减少约 17.27 MiB。RSS 增加约 5.17 MiB，没有 RSS 改善结论；CPU 也没有改善结论。

两版采样内部进程身份均固定，只汇总同一 resource / jetsam coalition 的进程。主窗口根据侧栏之后新增的唯一 WebContent 识别。`compare.py` 校验普通模式参数、七点采样、进程归属、任务库 / 设置一致性，并生成 `comparison.json`。

最终测试使用修改 bundle ID 后重新签名的发布版副本，文件签名哈希不同。`binary-equivalence.json` 检查除 Mach-O 签名指令和签名数据外，测试版与发布版的代码、数据和嵌入资源逐字节对应的哈希相同；没有重新编译测试副本。安装版和发布版完整文件 SHA-256 精确相同。

这是主窗口流程的短时收益，不能直接套用到此前所有窗口均使用后的 469 MiB RSS / 231 MiB footprint，也不能宣称没有长期泄漏。原有冷启动懒加载及侧栏缩小行为继续保留。

## 功能与诊断

最终版未保存草稿在关闭、重开和设置页往返后保留。滚动前后 AX 滚动条值都为 `0.6980803`，截图保存在 `screens/final-scroll-before.jpeg` / `final-scroll-after.jpeg`。原型也检查过相同恢复行为。

普通采样结束后，另起启用诊断的独立实例。隐藏时前端 viewport 为 1×1、根页面绘制已收起，原生 WebView frame 为 1×1；重开时前端恢复 1120×800，根页面恢复显示。两个快照的 DOM 元素数均为 242，App 仍为 created=1 / live=1，监听器、ResizeObserver 和 bridge 订阅计数完全相同；原生仍为两个附着 WebView。诊断会采集 Go 资料并执行 GC，未混入普通模式内存对照，不把该阶段的内存作为收益。

48 项原生断言通过，新增缺失窗口 / 非 WebKit 内容拒绝、可见窗口保护、1×1 缩小、窗口几何保持、重复隐藏后的正确恢复、自动调整模式及保存状态释放、复用和多 WebView 保护。前端检查为 0 错误 / 0 警告，19 项测试、Go 控制器与内部模块 race、构建中的集成测试及 vet 通过。Windows amd64 / arm64 交叉编译通过，没有 Windows 界面验收。

首次受限环境的正式构建在 iconutil 阶段报 Invalid Iconset，未生成新发布产物；按正常 macOS 构建权限重试后打包成功，失败日志保留。DMG、签名和安装版哈希校验通过。
