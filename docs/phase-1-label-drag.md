# 标签把手与普通模式拖动

日期：2026-10-07。macOS 本地预览构建 23。

## 行为

普通模式的任务标签拆为正文与边缘把手。平时保留细窄的主题色 / 到期状态标记，悬停把手时切换为点状抓手，并使用抓取光标。悬停仍可展开任务正文；点击正文查看卡片，单击把手不打开卡片。

无需先进入“整理桌面”，按住任一标签把手即可移动整组任务。开始移动的阈值为 5 个屏幕逻辑像素，避免轻微抖动误保存。上下移动调整位置，横向跨过屏幕中线可切换边缘；只操作当前显示器，目标边缘被另一组占用时拒绝保存。溢出入口同样提供把手。拖动期间停止悬停展开，松手保存，Esc / 失焦取消；保存失败还原位置并显示提示。编辑中的卡片及快速添加会阻止开始移动。

原整理模式仍提供独立的“移动整组”手柄与行内排序手柄，详见 [原整组移动记录](phase-1-stack-move.md)。标签把手移动整组位置，不改变任务顺序。

## 实现

- 沿用 `StackDragHandle` 的屏幕坐标差、指针捕获和 SQLite 移动事务，新增紧凑外观及拖动占用状态。开始移动等待宿主确认，松手只提交一次；失败不保留预览。
- 冻结拖动开始时的工作区、整组矩形与裁剪视口起点。macOS 普通侧栏只保留任务附近的短视口，计算位置必须补上该起点，否则会把屏幕中部的组误定位到顶部。
- 普通模式只保留工作区边缘间距；整理模式另为顶部手柄和底部工具栏预留空间。缩放与负坐标显示器继续使用已有平台换算。
- 被动侧栏仅在明确开始拖动时临时获得原生输入焦点，供 Esc 使用；不进入任务键盘选择模式，也不将 DOM 焦点从捕获的把手移走。正常完成 / 显式取消恢复原前台，失焦取消不抢回外部应用。主窗口不会因此被重新打开。
- 原生命中区域仍以每条标签为单位，内嵌把手不重复注册重叠面板。空白间隙继续透明穿透，不增加 WebView 或恢复全屏侧栏视口。

## 构建 24：点击焦点边框

键盘聚焦把手后再用鼠标点击，浏览器仍可能保留 `:focus-visible`，造成点击时出现 2px 焦点框。把手在按下时主动聚焦以保留拖动与键盘能力，仅依赖浏览器的输入方式判断不足以区分这个场景。

现记录当前是否由指针聚焦：鼠标点击 / 拖动时隐藏轮廓，也不因残留的焦点状态保持抓手高亮；键盘操作重新启用焦点提示，失焦清理状态。没有移除焦点、指针捕获或 Esc 能力。

浏览器实测同一操作序列：修复前轮廓为 `solid 2px`，修复后鼠标点击的轮廓样式为 `none`，键盘方向键仍为 `solid 2px`。再拖动 80 像素只保存一次，没有打开卡片。Svelte 检查、前端 24 项、打包 Go 测试与 vet 通过；Windows amd64 / arm64 交叉编译通过。此次仅调整前端焦点反馈，未重复既有原生命中区域测试。
