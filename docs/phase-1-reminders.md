# macOS · 到期状态与系统提醒

更新日期：2026-10-05。状态：已实现；本机授权、系统接收 / 送达记录、定时提交、关闭提醒和重启去重已验证。

## 使用

在“我的任务”中新建或编辑任务，设置截止时间后可勾选“提醒我”。默认关闭，已有任务迁移后也不会自动开启。首次启用时请求 macOS 通知权限；拒绝授权不会丢弃待发送提醒，界面说明如何允许，并提供“检查通知权限”入口。开启权限后补发到期的待发送提醒。

距离截止时间不超过 30 分钟时显示“即将到期”，到点后显示“已逾期”。普通桌面标签的标记分别使用琥珀色和红色，展开标签、主窗口及 Quick Card 同时显示文字状态；已完成、Snooze 中的任务不显示紧迫状态。只在状态边界更新时间，不用每秒刷新。

系统提醒需要 Sidelet 在后台运行；关闭主窗口只是隐藏，仍会提醒。完全退出后不会由本轮代码提前安排系统定时通知，下次启动会补发尚未发送的到期提醒。休眠唤醒和系统时钟变化会重新核对截止时间。桌面安静模式继续只控制桌面显示，明确开启的系统提醒由 macOS 通知设置控制。

Snooze 将系统提醒时间推迟到截止时间和 Snooze 结束时间中的较晚者，不改变 `DueAt`。更改有效提醒时间会生成新的提醒；仅编辑标题、取消桌面固定、完成后撤销 / 恢复不会重复发送已经交给系统的同一提醒。完成任务停止尚未发送的提醒，并请求移除对应系统通知；删除、关闭提醒或清空截止时间会清除提醒记录。

## 持久化与调度

数据库升级为 schema v2，在 `todos` 增加默认关闭的 `remind` 字段，继续使用现有 `reminders` 表。任务修改与提醒生成 / 取消属于同一个事务，失败一并回滚。提醒 ID 在同一有效截止时间内保持稳定；通知标识还包含资料目录的哈希前缀，独立测试资料不会取消正常资料的通知。

Go 调度器与任务修改共用串行工作队列，避免完成 / 删除与发送并发。只保留下一条待发送提醒的定时器；全部发送或没有提醒时不安装轮询。系统调用失败后一分钟重试；权限未允许时保留待发送状态，等待用户检查权限或应用再次激活。

macOS 使用 `UNUserNotificationCenter`。系统确认接收后记录发送凭据，并更新界面“提醒已交给系统”。历史字段 `delivered_at` 在本轮表示系统接口已接受请求，不意味着用户已看到横幅。重试时先核对系统的 pending / delivered 标识，恢复系统接受与数据库确认之间的崩溃窗口；已保存的凭据在用户清除通知中心后仍抑制重复发送。数据库与系统通知服务不能组成原子事务，不能承诺在“接受后、写凭据前崩溃且系统记录也已被移除”的情况下严格 exactly-once。

通知权限和前台通知行为依据 [Apple 的通知授权说明](https://developer.apple.com/documentation/usernotifications/asking-permission-to-use-notifications?language=objc)；待处理 / 已送达请求的核对使用 [UNUserNotificationCenter](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter)。系统通知点击会打开主窗口。
