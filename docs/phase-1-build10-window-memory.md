# 构建 10 使用后内存分项分析

2026-10-06，Apple M3 Max / macOS 26.6.2。本轮完成归因，没有修改产品实现或发布新构建。主窗口是最大的单项来源，其 WebContent footprint 约 83 MiB，其中约 52 MiB 被 vmmap 分类为图形资源。

证据目录：`build/results/build10-window-attribution-20261006/`，不进入 Git。`analyze.py` 可重新校验四个阶段并生成 `attribution.json`。

## 普通模式逐窗口归因

采用构建 10 的独立 bundle `dev.sidelet.workflow10`，与上一轮一样仅重新签名；二进制 SHA-256 为 `e13aefb7fbda6765847631ccdac9cfb5dd596604d7f57c17e729c5f8646df07b`。使用相同 13 条合成任务，其中两条固定。启动主窗口关闭；不启用内存快照、交互 fixture、指针追踪或强制 GC。

PID 79287 的 resource / jetsam coalition 为 25442 / 25443，独立于正在运行的正常应用。每个阶段只首次创建一个窗口，先完成全部 UI 操作，再等待 10 秒、采样 30 秒，间隔 5 秒，共 7 点。除首次创建之外复用原有窗口；各阶段内部 PID 集合固定。表中是中位数。

| 阶段 | RSS | footprint | 总进程 / WebContent |
| --- | ---: | ---: | ---: |
| 仅侧栏，后台启动 | 188.0 MiB | 63.2 MiB | 4 / 1 |
| 主窗口打开并隐藏后 | 287.5 MiB | 153.4 MiB | 5 / 2 |
| 快速添加 20 次取消后 | 355.5 MiB | 180.6 MiB | 6 / 3 |
| 浮动卡片 5 次编辑关闭后 | 444.8 MiB | 218.6 MiB | 7 / 4 |

侧栏、主窗口、快速添加和卡片分别对应首次出现的唯一 WebContent PID 79294、79649、80250、80912。分析验证同一应用进程、二进制、双重 coalition、预期进程数量及已有 WebContent 身份不变。快速添加 20 次均明确取消，卡片 5 次确认编辑窗口并关闭，没有保存任务修改。两次双击后 AX 未读到编辑窗口，随后按实际状态重试成功；原始观察保留，不将未确认的打开额外计为成功。

主窗口首次使用后，整体 footprint 增加约 90 MiB；快速添加再增加约 27 MiB；卡片阶段再增加约 38 MiB。阶段总差值还包含既有进程的变化，不能全部记到新窗口：例如卡片阶段主窗口自身约从 77 MiB 增到 83 MiB。

## 最终分项

| 进程 / 窗口 | PID | RSS | footprint |
| --- | ---: | ---: | ---: |
| 主窗口 WebContent | 79649 | 82.5 MiB | 83.3 MiB |
| Sidelet 主进程（含 Go、Wails / AppKit） | 79287 | 133.4 MiB | 41.9 MiB |
| 快速添加 WebContent | 80250 | 56.6 MiB | 26.1 MiB |
| 浮动卡片 WebContent | 80912 | 54.6 MiB | 25.9 MiB |
| 侧栏 WebContent | 79294 | 49.0 MiB | 18.8 MiB |
| WebKit GPU | 79292 | 53.1 MiB | 17.3 MiB |
| WebKit Networking | 79293 | 15.6 MiB | 5.4 MiB |

主窗口 WebContent 占最终 footprint 约 38%；快速添加和卡片分别约 26 MiB，侧栏约 19 MiB。主进程不能全部称为“Go 堆”：它还包含 Wails、AppKit 和其他原生分配。

这轮最终约 445 MiB RSS / 219 MiB footprint，上一轮完整工作流为 469 / 231 MiB。两轮操作不同：这轮没有打开设置、整理、完成 / 撤销或保存新任务，也有不同的卡片观察重试。产品实现未改变，不能把两轮差值说成优化收益。

## 内存分类

完成全部干净采样后，才对四个 WebContent、GPU 和主进程运行只读 `vmmap -summary`，输出保存在 `vmmap/`。分类读取没有混入普通模式采样。

主窗口的 `owned unmapped (graphics)` dirty 约 **52.0 MiB**，约为其 83.3 MiB footprint 的 62%。快速添加对应约 4.9 MiB，浮动卡片约 6.0 MiB，侧栏约 0.6 MiB。因此最明确的排查目标是主窗口保留的图形资源，而不是先调整少量任务对象。

主窗口 WebKit malloc zone 的分配量约 20.2 MiB，包含 WebKit 原生对象和引擎分配，不能直接当作 JavaScript 堆；JS JIT 生成代码 dirty 约 1.4 MiB，也不是完整 JS 堆。没有采集 JS 堆对象快照，不能据此排除 JS 泄漏。vmmap 的大量虚拟地址预留、共享系统库 resident 及图形资源 resident 不与采样 RSS 相加；本结论使用 dirty / footprint 口径。

源代码检查显示：主窗口隐藏只调用原生 Hide，TodoManager 及其草稿状态保持挂载；Quick Add / Quick Card 同样保留 WebView。普通模式没有持续的前端 setInterval，截止时间采用按需定时器，悬停 RAF 有结束边界。隐藏窗口仍保留图形资源已被测到，但是否持续绘制、以及每块资源的具体持有关系尚未直接验证，不能把保留内存定性为持续渲染或泄漏。

最终空闲阶段约为一核 0.70% CPU，其中主窗口约 0.14%、快速添加约 0.15%、卡片约 0.13%、GPU 约 0.26%。这只是 30 秒短样本，不作长期 CPU 结论。

## 下一步试验与保留条件

优先试验主窗口隐藏时收起页面绘制内容、再次显示前恢复布局，同时保持组件实例、未保存草稿和滚动状态。目标是测量图形资源是否下降；52 MiB 是已定位的资源量，不是承诺可全部释放的收益。需要有普通模式同流程对照，并确认隐藏 / 重开后草稿、设置往返、焦点及窗口数量正常；没有稳定收益就撤回试验。

此前销毁 Quick Add 的试验因 WebKit 进程保留增加已撤回，本轮没有重做窗口销毁策略。多屏、Spaces、真实全局按键、中文输入法及休眠验收状态不变。
