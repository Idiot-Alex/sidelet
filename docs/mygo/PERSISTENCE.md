# MyGo 独立资料与重启恢复

2026-10-08 开始，2026-10-09 完成。`-native-main` 默认启用持久化，首次启动为空列表。资料使用标准库 JSON 与原子文件替换，保持全原生入口不依赖 Wails、WebView 或 SQLite；这是独立实验资料格式，没有迁移或导入正式 Sidelet 数据。

## 运行与隔离

```bash
bash experiments/mygo-sidebar/build-macos.sh
open -n build/bin/mygo-lab/SideletMyGoLab.app --args \
  -native-main -data-dir "$PWD/build/results/mygo-persistence-manual"
```

不传 `-data-dir` / `-output` 时，macOS 默认目录是 `~/Library/Application Support/SideletMyGoLab`。Windows 使用 `os.UserConfigDir()` 下的 `SideletMyGoLab`。显式 `-data-dir` 优先；只传 `-output` 时资料放在输出目录的 `profile/`，宿主数据在 `app-data/`，便于隔离验证。目录包含 `profile.json` 与用于进程锁定的 `profile.lock`；锁文件保留不代表应用仍在运行。

程序拒绝默认正式 Sidelet 目录及其子目录，也拒绝包含 `sidelet.sqlite3` 的目标目录。每个目录只能有一个持久实验进程写入；第二个进程启动失败，不覆盖资料。macOS 使用 `flock`，Windows 使用 `LockFileEx`；Windows 目前只有交叉编译结果。

`-native-main -memory` 保留三条合成任务，退出后重置；不能与 `-data-dir` 同时使用。无参数的旧侧栏实验及 `-hybrid` 仍为内存模式。

## 保存内容与失败处理

当前资料版本为 `schema: 2`，包含随机资料标识、稳定任务槽位与删除标记、任务版本、标题 / 备注 / 重要程度、固定 / 完成 / 临时状态、截止时间 / 提醒 / 稍后、手动顺序、主题、边缘 / 中心比例 / 密度、撤销对象与截止时间、提醒代次及已接受回执，以及应用偏好。删除不复用任务 ID，排序不改变 ID 或编辑版本。未提交草稿、悬停、卡片、整理模式、安静模式和拖动预览不保存。

版本 1 可自动升级：保留原任务、布局、提醒代次 / 回执和资料标识，主题沿用旧值，Dock 默认显示，启动窗口默认打开以保留旧实验行为；升级采用同一原子提交。新资料使用正式 `internal/settings.Value` 的默认值，启动窗口偏好默认关闭，但首次创建资料时仍显示主窗口。后续启动按照已保存偏好；`-main` 强制打开，`-main-hidden` 强制隐藏，两者互斥。

设置页可保存启动窗口偏好、默认边缘与密度、Dock 显示。默认值不修改现有任务组的布局；目前仍为一个任务组，只在初始化新资料时应用默认值，多任务组创建尚未迁移。Dock 仅 macOS 可用：先建立独立菜单栏入口，再切换应用策略，保存失败时补偿恢复旧策略。菜单栏提供任务窗口、快速添加、安静模式、设置和退出入口；应用菜单 `⌘1` 和 Dock 重开也可恢复任务窗口。JSON / CSV 导出复用正式格式与原子写入，读取点击时最近一次持久提交，禁止写入本资料目录，详见 [导出记录](EXPORT.md)。macOS 登录启动已接入，实际系统状态独立于保存偏好，注册 / 文件失败会补偿恢复；状态检查不重新注册。详见 [登录启动记录](LOGIN_STARTUP.md)。

安静模式只隐藏侧栏 / 卡片、关闭编辑与整理会话、取消拖动并撤销鼠标区域，不停止系统提醒，不改变已提交任务或主窗口草稿；恢复时重新显示标签，重启后恢复正常显示。提醒接受与回执保存沿用上述持久化路径。

每次提交先克隆模型，校验后写入同目录临时文件，文件权限为 0600，完成文件同步后原子替换旧文件。替换前失败会恢复内存模型，保留旧资料、任务版本、提醒代次与编辑草稿，界面显示保存失败；主题预览和拖动位置也回到已保存值。内容未变化时不写文件，后台检查不会掩盖尚未解决的保存错误。目录同步在替换后尽力执行，不能承诺突然断电下的绝对持久性。Windows 文件权限不等同于 macOS POSIX 权限。

启动读取限制为普通文件、最多 64 MiB；拒绝未知字段、尾部额外内容、非法任务 / 排序 / 提醒状态与未支持的版本。损坏资料不自动重置，原文件保留，错误写入启动日志；尚未提供 GUI 修复或备份恢复。实验只维护一个当前资料文件。需要人工检查时先退出使用该目录的应用，保留文件副本，再选择新的独立目录启动。

完成撤销保留原来的 5 秒期限。重启时仍在期限内可以撤销；已到期的临时完成任务启动时清理，避免重新延长撤销窗口。任务与提醒的运行期间清理仍使用单次唤醒。

普通持久模式不记录完整任务快照。显式 `-output`、`-log-file` 或 `-trace-input` 的诊断会包含任务内容，证据仅使用合成数据。

## 提醒恢复

提醒使用 `sidelet-mygo.profile.<profileId>.<generation>` 标识；代次在发送前落盘，截止时间 / 稍后改变时生成新代次，标题编辑不会生成新提醒。系统接受后单独保存回执，不增加任务编辑版本。回执保存失败时保留未确认状态，稍后查询系统记录再补记，避免已有记录重复发送。

持久模式退出不清除该资料的系统记录，以支持系统接受后、回执落盘前的重启恢复；关闭提醒、完成或删除仍只清理本资料已失效的记录。内存模式沿用本次运行的随机命名空间并在退出清理。通知权限是独立应用 `io.sidelet.mygo-lab` 的 macOS 权限。

应用退出期间不会运行提醒计时器；重开后检查尚未发送的到期任务。若系统已接受、回执尚未保存，又在重启前被用户从系统中清除，则没有足够信息证明该代次已发送，不能承诺此边界下绝对不重复。已有持久回执不受系统记录被清除影响。
