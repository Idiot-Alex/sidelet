# WebView SQLite → MyGo 迁移

2026-10-17，Sidelet 0.2.0 build 30。

## 使用

退出新旧 Sidelet，在终端运行（源参数是旧资料目录）：

```sh
/Applications/Sidelet.app/Contents/MacOS/sidelet \
  -import-webview "$HOME/Library/Application Support/Sidelet"
```

默认目标为 `~/Library/Application Support/SideletMyGoLab`；`-data-dir` 可指定独立目标。命令只迁移并输出任务数量、备份位置及是否已导入，随后退出，不启动窗口或通知。Windows 可调用同一可执行文件和参数，但实机迁移尚未验证。

## 数据与保护

- 仅支持旧 SQLite schema 2、一个任务组。未知版本、损坏库、多任务组、非法字段会报错；不静默丢弃或合并。
- 旧库以只读连接打开，不调用旧版 `Open` 的升级或清理逻辑。`VACUUM INTO` 将提交的 WAL 数据包含在独立备份中，再读取备份校验结构、完整性与外键。
- 备份位于目标资料 `legacy-backups/<时间-随机后缀>/`，包含 `sidelet.sqlite3`、存在时的旧 `settings.json`、存在时的 `native-profile-before.json`。目录 0700，文件 0600；备份同步完成后才写入目标事务。原文件保留。
- 目标有 MyGo 任务（包括已删除槽位）时拒绝覆盖。已有空 JSON 会校验、备份并保留资料 ID，原 JSON 不改动；无目标资料则生成 ID。
- 任务标题、多行备注、完成及完成时间、固定状态、临时状态、截止及稍后时间、优先级、创建/更新时间、提醒开关与对应回执都会保留。旧优先级 1 归入当前“普通”(0)，2/3 保持不变。
- 主题、默认偏好、主窗口/Dock 偏好和单组侧栏的位置/密度会导入。登录项仅复制偏好，不自动注册系统服务。
- 原任务 ID 到新槽位的映射、原布局（含屏幕标识）、源目录、备份路径、备份 SHA256 与导入时间保存在资料迁移凭据中。当前 UI 使用单组布局，新版导出仍使用新编号，屏幕标识尚未投影到新版导出。
- 任务和凭据同一 SQLite 事务提交。写入失败一并回滚，可重试；同一资料再次导入相同源目录会跳过，源库后续变化不会再次合并；导入其他源目录会拒绝。
- 提醒使用新版独立编号，匹配原有效提醒时间的已发送回执保留，避免重复发送。正常启动仍执行现有到期/临时任务清理规则；旧备份保留导入时的完整快照。

## 验证

全量测试、race、vet、Mac 构建/签名通过；Windows 双架构交叉构建通过。测试覆盖 WAL 快照、保留旧临时完成行、未来 schema 拒绝、字段/主题/布局/回执恢复、正常保存后凭据持久化、重复导入跳过、目标任务保护、空 JSON 备份、模拟写入失败事务回滚及重试。

本机先在隔离目标试迁移：3 条任务字段逐项匹配，源库/设置哈希不变，重复导入跳过。之后迁入日常目录，核对布局和提醒回执，`quick_check=ok`；原库、设置、原 MyGo JSON 哈希未变。

安装后的原生窗口确认 2 条待办、1 条已完成，共 3 条；快捷键显示已启用。旧 WebView 应用备份于 `build/results/legacy-migration-20261017/Sidelet-WebView-build25.app`，当前 `/Applications/Sidelet.app` 为 build 30。证据与含用户数据的备份均在忽略目录或个人资料目录，不进入 Git。

## 回退

退出新版，将备份的旧 WebView 应用放回 `/Applications/Sidelet.app`，旧库仍可使用。切换后在 MyGo 新增或编辑的内容不会反向同步到旧库；回退前应先从新版导出。build 29 及更早 MyGo 不认识新增迁移元数据，应使用 build 30 读取新资料。
