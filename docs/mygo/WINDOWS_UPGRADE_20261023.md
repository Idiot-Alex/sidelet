# Windows 旧库升级与草稿保留验收

2026-10-23，build 43。此轮补充打包应用测试、安装器验收及包内说明，不改变桌面运行逻辑。

## 新增检查

此前安装器升级测试使用同一个程序配上较低的安装器版本，能验证 EXE 替换、拒绝降级和资料保留，但不能证明旧数据库由打包后的应用完成升级。

`TestPackagedApplicationUpgrade` 创建与 build 42 相同结构的 SQLite v1 合成资料，包含中文、多行备注、任务版本、排序、主题、完成状态与已有提醒回执；保存升级前备份，随后启动真实打包程序。测试先用普通 SQL 核对 schema 已变为 v2、草稿表已创建，再使用业务读取器检查数据，避免测试读取器自行迁移导致假通过。

升级后经常规持久化接口写入新建草稿，第二次启动实际程序，检查主窗口恢复的草稿、全量任务 / 设置 / 回执一致性、SQLite 完整性以及正常退出后资料锁释放。升级前备份保持不变。夹具只模拟旧版数据结构，没有声称运行历史旧 EXE；不读取日常资料。

Windows CI 将它作为单独的 `packaged-upgrade.jsonl` 运行。安装器的首次安装、运行中升级拦截、升级后启动和卸载重装后的启动检查，同时比对完整新建草稿：中文标题、多行备注、重要程度、固定状态、未填完的日期、提醒 / 临时选项和备注 / 选项展开状态。

## 交付说明

ZIP 与安装器内的使用说明新增草稿恢复范围和 SQLite 回退约束。build 43 首次启动会把原生库升级到 v2；build 42 及更早应用不能直接读取。回退需升级前的完整备份，并保留升级后新增的数据。实机检查表新增草稿、保存失败、旧库升级以及安装 / 重装场景，仍明确标记待测。
