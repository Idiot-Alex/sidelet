# macOS 主窗口按需加载与内存试验 · 构建 8

后续主窗口单独对照与两项撤回的渲染试验见 [主窗口内存排查](phase-1-main-memory.md)；该排查没有发布新构建，约 15 MiB 的完整归因仍未完成。之后独立完成的 Quick Card 按需加载已发布构建 9，见 [构建 9 记录](phase-1-quick-card-memory.md)。下文保留构建 8 的历史结果。

2026-10-06，Apple M3 Max / macOS 26.6.2。证据目录：`build/results/memory-build8-20261006/`，不进入 Git。

## 发布行为

关闭“启动时显示主窗口”时，不创建任务 / 设置 WebView。Dock、菜单栏、设置入口、第二实例和通知点击需要主窗口时才创建；等待前端订阅就绪后发布页面选择、布局和任务，再显示窗口。后台主题 / Dock 偏好、提醒、侧栏布局不依赖主窗口存在。

主窗口打开后继续复用，隐藏时保留编辑草稿。快速添加保持首次使用时创建、后续复用的现有行为；切到其他应用保留草稿，取消 / 保存成功清空输入。**最终版本没有启用自动销毁快速添加窗口。**

诊断快照新增 `controllerViews`，按实际已加载页面等待回复；历史三 / 四页面快照仍可读取。诊断本身不创建主窗口。关闭钩子将操作交给 UI 队列；窗口来源按对象身份判断。

## 回收试验为何撤回

试验在取消 / 保存成功后的 90 秒关闭快速添加。对象快照确认挂载 WebView 从 4 个降到 3 个，原生绑定从 3 降到 2，观察器从 12 降到 8；下次打开能够重建。标题和选项在失焦 123.8 秒后保留，保存成功后的回收也通过。

但普通模式中，窗口关闭后 WebKit 进程及内存仍保留。再次打开快速添加新增一个属于同一 resource / jetsam coalition 的 WebContent 进程：

| 阶段 | WebContent 数 | 总 RSS | 总 footprint |
| --- | ---: | ---: | ---: |
| 回收后、重建前 | 4 | 399.0 MiB | 205.3 MiB |
| 重建并取消后立即 | 5 | 450.8 MiB | 208.1 MiB |
| 再次回收后继续观察 | 5 | 450.1 MiB | 206.5 MiB |

最后一次观察在重新打开约三分钟后、第二次回收约 86 秒后，说明该范围内并非只在创建瞬间重叠。RSS 汇总会重复计算共享页，不能把新增 RSS 全部解释为独占物理内存；footprint 也未显示明显下降。具体缓存 / 对象引用的归因未完成，没有宣称已经排除泄漏，也没有杀死 WebKit 辅助进程制造下降。

因此撤回自动销毁，保留窗口复用，避免每次重新打开增加保留进程。试验二进制留在 `recycling-experiment/Sidelet.app`，SHA-256 为 `bccd6d6eeede5bdda5aba19cabcec3602665c018f1b9766b86369a025e234bf5`。初版试验快照来自 `5d8ea22d54c996593def686406ae42953a5e24a62cb060d0aa9b741190492529`。名称中含 `final` 的早期采样仍属于回收试验，最终发布结果使用 `build8-reuse-*`。

## 验证范围

两个独立测试资料目录来自同一 13 条合成任务的 SQLite 备份、相同偏好；关闭诊断模式。每个版本冷启动预热 20 秒、采样 60 秒；随后打开任务窗口，执行 10 次快速添加 / Esc 取消，隐藏主窗口并采样 130 秒。恢复比较只取采样最后 30 秒，避开操作峰值。RSS 和 footprint 均包含 Sidelet 与同时匹配 resource / jetsam coalition 的 WebKit 进程。

这是短时改动验证，不替代构建 7 的十分钟稳定性基线，也不说明完整 P0 验收已通过。首次打开主窗口增加一次加载；打开后保留窗口与草稿，不能期待一直保持冷启动占用。

主窗口编辑草稿在三套主题切换、导出取消和返回任务页后保留。快速添加试验的失焦草稿验证只保存一条合成任务，固定成功、无截止时间 / 无提醒；普通对比只取消，不创建任务。所有测试使用独立资料。

前端检查为 0 错误 / 0 警告，19 项前端测试通过；Go 内部模块与控制器 race / vet 通过，回退后再通过 Quick Add / 集成 / 控制器 race。历史稳定性分析兼容及新增快照检查共 8 项通过，实际构建 7 旧数据也可复核。Dock 原生检查新增无主窗口场景，共 12 项通过。Windows amd64 / arm64 交叉编译通过，未验证 Windows 界面。

## 最终发布测量与安装

| 场景 | 构建 7 RSS / footprint | 构建 8 RSS / footprint | WebContent 数 |
| --- | ---: | ---: | --- |
| 后台冷启动 | 324.8 / 136.6 MiB | 240.2 / 92.1 MiB | 3 → 2 |
| 打开主窗口并使用快速添加后 | 408.3 / 187.8 MiB | 401.9 / 202.8 MiB | 4 → 4 |

后台冷启动 RSS 减少 84.6 MiB（26.1%），footprint 减少 44.5 MiB（32.6%）。打开主窗口后，RSS 只减少约 6.4 MiB，footprint 反而增加约 15.0 MiB，主要差异落在按创建顺序推断属于主窗口的 WebContent；原因尚未定位，不能宣称使用后整体内存已改善。最终版 130 秒恢复期间进程集合不变，WebContent 保持 4 个。

无需主窗口的入口另用最终版诊断实例验证：冷启动只有 Stack / Quick 两页，外部测试入口打开快速添加后只有 Stack / Quick / Add 三页；重复打开保留相同三个 WebContent PID，桌面键盘操作和 Quick Card 也不创建主窗口。该入口是 fixture-request，不能作为真实全局按键通过证据。

最终构建 8 已安装到 `/Applications/Sidelet.app`，签名校验、Dock 重开、任务页及快速添加 / 取消烟测通过。升级前后的全部数据库表（含序列表）精确相同，设置文件逐字节相同，仍为原两条任务，完整性和外键检查通过。所有测试实例退出，正常应用按保存的偏好重新后台启动；两个快捷键注册成功，登录启动仍关闭，通知仍允许。启动恢复后不再次打开主窗口，避免烟测抵消按需加载的效果。
