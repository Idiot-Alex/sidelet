# Quick Add / Quick Card 共用窗口与构建 14

2026-10-06，Apple M3 Max / macOS 26.6.2。构建 14 已安装到 `/Applications/Sidelet.app`。本轮减少了 WebContent 进程和 RSS，整组 footprint 的降幅有限，不能描述为明显降低系统内存压力。

## 实现

macOS 上互斥的快速添加与浮动任务卡片共用一个按需创建的 WKWebView。每次切换先隐藏窗口、配置原生输入模式和尺寸，等前端切换并确认布局后显示。两个逻辑会话仍然独立；展示代次与会话代次一起校验，拒绝已关闭或上一次展示的延迟消息，避免误取消和误保存。

快速添加组件首次使用时挂载，切换到卡片时保持隐藏，以保留未提交草稿；隐藏后停止预览请求和聚焦。取消或保存成功后仍清空草稿。原生窗口仅绑定一次，窗口标题和直接输入模式可以双向切换。

默认在 macOS 开启，可以用 `-shared-popup=false` 回到独立弹窗作为对照。Windows 保持独立窗口。主窗口继续保留完整视口，[构建 11 的隐藏视口试验](phase-1-full-window-memory.md)仍处于撤回状态。

## 完整流程对照

两份相同初始合成资料，各 13 项任务、2 个固定任务。使用同一个构建 14 二进制的独立签名副本，仅共享开关不同；排除 Mach-O 签名段后的代码与数据哈希一致。采样通过资源与 jetsam 两个 coalition ID 归属进程，正常用户实例不计入。

每组经过 2 次设置访问、整理进入退出、任务完成及撤销、20 次快速添加（第 10 / 20 次保存）、5 次卡片编辑后关闭不保存，以及组间重开主窗口。结束时各 15 项任务，除操作时间戳外所有表一致，设置文件逐字节相同。隐藏主窗口后预热 10 秒，空闲采样 30 秒、间隔 5 秒，各 7 点；成员 PID 与启动时间不变，期间没有界面操作、强制 GC 或窗口销毁。

| 指标（中位数） | 独立窗口 | 共用窗口 | 差值 |
| --- | ---: | ---: | ---: |
| WebContent 数 | 4 | 3 | −1 |
| 应用及 WebKit 进程数 | 7 | 6 | −1 |
| RSS | 474.44 MiB | 436.03 MiB | −38.41 MiB |
| footprint | 230.65 MiB | 228.58 MiB | −2.06 MiB（约 0.9%） |
| 快速添加 + 卡片 / 共用弹窗 footprint | 52.00 MiB | 24.53 MiB | −27.47 MiB |
| 主窗口 footprint | 88.22 MiB | 109.09 MiB | +20.88 MiB |
| 侧栏 footprint | 21.24 MiB | 27.03 MiB | +5.80 MiB |

整组 footprint 的范围分别为 230.60–232.12 MiB 和 228.57–228.66 MiB。平均空闲 CPU 分别约为单核的 0.73% 和 0.51%，短采样不足以证明持续 CPU 收益。RSS 包含共享驻留页，不能把 38 MiB RSS 降幅等同于系统实际少占用 38 MiB。

共用版本在主窗口重开后的辅助功能点击上发生多次自动化超时，改用已观察截图的坐标继续；退出整理后也经过重开入口才读取到主窗口。独立版本没有同样的重试，因此两组耗时和激活顺序并非严格一致。两组均完成并记录相同的功能流程，但不能据此确定主窗口增加的原因，也不能把局部 27 MiB 收益推广为整组收益。保留这项减少物理窗口和进程的实现；目前对实际内存压力的改善很小，后续主要定位主窗口的图形缓存和分配。

完整对照使用的是构建 14 候选；最终代码复核追加了原生 `WindowClosing` 消息的展示代次保护，并补充延迟关闭不能影响新卡片的控制器测试。最终包重新通过 race、打包检查和 Windows 交叉编译，未重新进行内存采样；上述数字保留为候选的原始测量。

独立功能资料验证了 Add → 主窗口 → 卡片编辑关闭 → Add 的草稿保留，取消后的清空、时间识别与保存、卡片实际保存，以及三种主题的两类弹窗。原生检查共 42 项通过，包含同一窗口反复切换时状态、WebView 与绑定复用。外部应用真实失焦、多屏、Spaces、硬件全局快捷键和中文输入法未由这组自动化证明。

前端检查 0 错误 / 0 警告、19 项前端测试、Go 控制器和状态模块 race、打包中的存储 / 提醒 / 设置 / 导出 / 快速添加 / 集成测试与 vet 通过。macOS arm64 签名与 DMG 验证通过；Windows amd64 / arm64 交叉编译通过，Windows 界面未验收。
