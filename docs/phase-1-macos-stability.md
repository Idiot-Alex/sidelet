# macOS 安装版性能与稳定性记录

当前构建 7 的复测及内存原因分析见 [构建 7 稳定性记录](phase-1-build7-stability.md)。本文保留构建 2 的历史采样，不用旧结果替代新增功能后的资源测量。

2026-10-05，针对 `/Applications/Sidelet.app` 的 0.1.0（构建 2）进行复测。沿用 [P0 性能记录](phase-0-macos-performance.md) 的 CPU、RSS、physical footprint 口径；内存预算尚未冻结，不根据 RSS 单独判断泄漏。

## 场景与隔离

本轮证据目录为 `build/results/stability-native-20261005/`。关闭正常实例，在独立资料目录复制两条既有人工测试任务。正常资料库在前后只读比对，测试结束后恢复正常安装版。

1. 无额外诊断的空闲实例：主窗口隐藏，两条固定任务，预热 30 秒，每 5 秒采样，持续 600 秒。不启用 `-memory-dir`、`-interaction-test` 或鼠标追踪。
2. 同一安装版二进制的操作实例：启用现有内存快照与键盘测试入口，分批打开 / 关闭实际 Quick Card 和设置页，执行任务操作。快照覆盖 Go GC 后堆、goroutine、原生弱引用计数与三个前端视图的注册 / DOM 数量。
3. 操作结束隐藏主窗口，再记录完整十分钟恢复。诊断实例会轮询快照请求、强制 Go GC，并受到 Computer Use 读取界面的影响；其 CPU 不能代替第一项的正常空闲基线。

卡片通过项目夹具进入原生键盘模式，再操作真实 WKWebView。这个入口不证明硬件全局快捷键到达，也不替代 Passive 鼠标悬停 / 拖动测试。

## 重复操作

通过实际 UI 逐次确认：60 次卡片开关、30 次设置页往返、5 次完成 / 撤销、5 次延后 30 分钟 / 现在恢复，以及 5 次创建临时任务 / 完成 / 五秒后清理。临时任务均固定到桌面，并设置 2027-01-01 的未来提醒；清理后测试库恢复两条常规任务，临时任务和提醒记录为零，完整性检查为 `ok`，无外键错误。

第 15 次卡片操作前，出现一次入口进入 KeyboardActive 后随前台通知退回 Passive，随后三次夹具点击没有使入口生效。显式激活夹具后继续完成。它与 Computer Use / 夹具的前台切换同时发生，不能据此断言真实硬件快捷键有问题或没有问题。四次入口失败单独保存在 `retries.jsonl`，不计入成功循环；误在中断处取得的两个快照由 `phases.json` 明确排除。

## 十分钟恢复与保留内存

最后关闭时刻为 03:42:12（本机时间），进程采样覆盖其后 607.57 秒；完整交互 / 恢复采样共 260 点，6 个进程身份全程未变。恢复第 570–600 秒的 6 个样本中，总 RSS 中位数 **404.64 MiB**，footprint 中位数 **177.01 MiB**。操作结束快照附近 RSS 为 405.17 MiB，静置后下降约 0.53 MiB；与诊断实例采样首值 315.59 MiB 相比，仍保留约 89 MiB。

第 20 / 40 / 60 次卡片与对应设置批次快照附近 RSS 分别为 353.89 / 369.19 / 378.72 MiB。这些是距快照两秒左右的单点，含 UI 观察和引擎回收时机影响，只描述趋势，不充当阶段中位数或泄漏斜率。footprint 交互峰值受 GPU 波动明显影响，不能用它的下降宣称内存完全释放。

最终 Go GC 后 HeapAlloc 为 **2545.34 KiB**，较操作结束的 2599.00 KiB 回落；goroutine 仍为 15，附着 WebView 为 3，接收面板存活 / 持有为 2 / 2，AppKit 窗口计数为 7，其他已统计监听与组件没有增加。恢复期间 SQLite 主文件、WAL、SHM 的大小和修改时间均未变化。

恢复第 30–600 秒的单核 CPU 加权平均为 **0.48122%**、区间峰值 **0.88642%**。此运行开启诊断，且在恢复阶段对一个 WebContent 做过三秒 `sample`，不以它替换正常空闲预算。采样主要是事件等待与少量 WebCore 定时器处理，没有取得足以定位某个业务循环的调用证据。保留采样和 Go 堆差异文件，避免把诊断实例的差异直接归因于应用泄漏或全部归因于诊断工具。

结论：本轮未发现进程 / 窗口 / 已统计监听与 goroutine 随重复操作累计增长，结束后的内存趋于平台期；仍存在显著 RSS 保留，尚未完成完整 JavaScript 引用链或全天运行分析，不宣称零泄漏。原有真实鼠标、全局快捷键完整流程、多屏 / Spaces、休眠及登录启动验收保持原状态。

## 普通模式操作后的短对照

为补充诊断实例 CPU 偏高的观察，关闭诊断实例，用同一安装版和独立测试库重新启动，不带 `-memory-dir` 或 `-interaction-test`。实际执行 3 次设置页往返、3 次完成 / 撤销，以及 1 条带未来提醒的临时任务创建、固定、完成和清理。主窗口隐藏后预热 30 秒，每 5 秒采样，共 **180.022 秒 / 37 点**。

单核 CPU 加权平均 **0.30914%**，中位数 **0.29708%**，区间峰值 **0.51614%**；总 RSS 中位数 **346.52 MiB**，首尾 **346.47 → 346.53 MiB**，6 个进程成员未变。平均值低于首轮目标，单个区间超过 0.5%；完整保留，没有剔除。操作后 CPU 高于未显示主窗口的初始空闲状态，不能声称额外活动全部由诊断导致。此对照只有三分钟，操作量也较小，不能替代完整十分钟操作后无诊断验收或证明卡片场景的根因。

## 收尾

所有测试实例和夹具已退出，恢复 `/Applications/Sidelet.app` 的正常资料目录并打开“我的任务”。正常数据库各表和 `settings.json` 前后逐项相同，仍为零任务，登录启动关闭，通知授权保持允许；正常 / 测试数据库完整性均为 `ok`，测试库无外键错误、临时任务或提醒记录。应用二进制及已有 DMG 未修改，本轮新增的是采样分析工具、4 项分析器检查和记录文档。

保留的后续观察项：全天运行、无诊断的完整操作后长采样、RSS 保留的完整对象归因，以及入口焦点中断在真实硬件输入下是否复现。本轮不将完整 P0 或内存验收升级为通过。

## 复核工具

```sh
python3 scripts/analyze-macos-stability.py --dir build/results/stability-native-20261005
python3 scripts/test-macos-stability-analysis.py
```

分析器读取原始进程采样、逐次 UI 成功记录、阶段时间和对象快照。拒绝空闲不足十分钟、诊断参数混入空闲基线、两轮二进制哈希不同、缺失 / 重复 / 失败操作，以及恢复不足十分钟。最后 30 秒的恢复统计排除操作时峰值；输出的 `evidenceComplete` 仅表示所需证据齐全，不表示零泄漏或完整 P0 验收通过。
