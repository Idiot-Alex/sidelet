2026-10-06，Apple M3 Max / macOS 26.6.2。证据目录：`build/results/stack-viewport-build10-20261006/`，不进入 Git。构建 10 已安装到 `/Applications/Sidelet.app`。

## 实现

macOS 的 Stack 窗口缩到任务所在的垂直区域，上下保留约 10 个逻辑像素。宽度保持可容纳悬停展开的范围。位置比例、列表容量和溢出数量仍按完整 WorkArea 计算，前端将任务位置换算为缩小窗口内的坐标，Quick Card 使用实际窗口原点定位。

整理模式和 5 秒撤销提示出现时恢复完整高度，退出或提示过期后重新缩小。任务完成、稍后提醒到期、固定关系改变时，前端沿用已有状态与截止时间更新，通知控制器重新计算视口；没有新增普通模式的空闲轮询。窗口尺寸改变后的命中区域回复携带布局序号，旧视口回复不再缩放后覆盖新区域。等待 Svelte 更新后才测量 DOM。

空任务保留约 20 像素的透明窗口，命中区域为零；不销毁 WebView。窗口移动、任务排序、跨边缘预览和数据库位置语义保持原有设计。Windows 保持完整高度，完成交叉编译但未验证其界面。

## 普通模式内存对照

两版使用相同 13 条合成任务，其中两条固定；相同主题、右侧 35% 位置与普通密度，关闭启动主窗口、诊断和交互测试。冷启动及首次双击 Quick Card 编辑、关闭后各预热 15 秒、采样 30 秒，间隔 5 秒，共 7 个点。表中为中位数，包含 Sidelet 与同时匹配 resource / jetsam coalition 的 WebKit 进程。

| 场景 | 构建 9 RSS / footprint | 构建 10 RSS / footprint | WebContent 数 |
| --- | ---: | ---: | --- |
| 后台冷启动 | 188.0 / 69.2 MiB | 187.4 / 63.1 MiB | 1 → 1 |
| 打开卡片编辑并关闭后 | 260.6 / 99.2 MiB | 261.4 / 95.1 MiB | 2 → 2 |

冷启动 footprint 减少 **6.03 MiB（约 8.7%）**，使用卡片后减少 **4.14 MiB（约 4.2%）**。RSS 变化均不到 1 MiB，不能宣称其明显下降。冷启动一核平均 CPU 约 0.012% / 0.013%，使用卡片后约 0.296% / 0.205%；短时样本不支持长期 CPU 改善结论。

两版有效采样阶段的进程集合均不变，没有通过杀死 WebKit 进程制造下降。RSS 汇总包含共享页，footprint 是进程记账指标；收益不能直接套用到其他屏幕、任务数量或操作流程。本次没有测量打开主窗口、整理或撤销之后的完整长期恢复曲线，也不证明构建 8 / 9 先前的所有 footprint 差异已经定位或解决。

同轮有效基线为独立重启后的 `before-clean.log`。最初基线与正常应用短暂共存的启动没有用于采样。分析可运行证据目录的 `analyze.py`，会校验二进制、普通模式参数、采样长度、双重 coalition 归属及测试数据一致性。其他失败的 UI 观察与快照用途见 `plan.json`，原始证据保留。

## 几何与交互验证

- 两条任务：原完整视口约 1008 像素，缩为 **116**；原生窗口为 312 × 115。命中矩形仍位于屏幕 y=338 / 388，Quick Card 仍位于 y=326。退出整理后恢复完全相同的任务命中矩形。
- 整理：完整工作区高度恢复，手柄与工具栏可见；键盘进入预览、Esc 取消、完成整理回到锁定模式。预览没有保存位置。
- 完成 / Undo：撤销提示出现时恢复 1007 的原生高度；点击撤销后恢复单任务 65 的高度。等待完成提示过期后，空任务窗口为 21 高、零命中区域。
- 溢出：固定九条合成任务，原生窗口为 465 高、九个命中区域（八条任务加溢出入口）；入口打开正确的剩余任务卡片。
- 键盘卡片：独立 fixture-request 打开任务 / 溢出卡片并 Esc 退出通过。该入口不是全局硬件按键证据，未补充真实鼠标拖动、多屏 / Spaces 或休眠验收结论。

原生路由 **39 项**全部通过，新增裁剪后的屏幕命中矩形、独立路由、间隙 / 空白穿透、弹出位置原点及输入 helper 复用断言。首次新增断言使用固定 CSS 尺寸，AppKit 调整内容区多出一个点后比较失败；改为与实际前端一样回报真实 viewport 尺寸后，两次测量矩形完全相同，最终日志为 `native-routing-final.log`。三套主题的真实 WKWebView alpha 回归通过，空白和圆角仍透明。

独立诊断资料允许合成任务完成 / 撤销及固定关系改变，不用于普通内存比较。普通对照的两份任务库及设置精确相同。Go 视口边界测试覆盖零 / 单 / 多任务、超高列表、密度、顶部 / 底部位置、短工作区和完整高度回退。Go 控制器与内部模块 race、构建中的集成测试 / vet、前端检查（0 错误 / 0 警告）及 19 项测试通过；Windows amd64 / arm64 交叉编译通过。
