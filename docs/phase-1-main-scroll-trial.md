# 主窗口固定视口试验（已撤回）

2026-10-06，Apple M3 Max / macOS 26.6.2。安装版保持构建 14；本轮没有获得可发布的内存优化。

## 修改与决定

试验给任务页 / 设置页增加一个固定 `100vh` 的容器，使用 `overflow:auto; contain:layout paint`，并将页面切换后的滚动复位改为容器滚动。目的是让网页根绘制区域不随页面高度变化，任务组件继续保留草稿；没有缩小原生 WebView 或销毁窗口。

**实测图形占用更高，整个修改已撤回。** `App.svelte` 与试验前副本逐字节相同，前端产物已经重新构建。候选仅在独立应用中运行，没有替换 `/Applications/Sidelet.app` 或生成新发布包。

## 分类结果

基线来自最终安装构建 14，候选由同一工作区编译，仅改变上述容器 / 滚动复位和试验构建标识。两份应用使用不同 bundle / 显示名称与相同的 13 项合成任务、2 项固定任务、Mac 主题；正常用户实例保持运行。

每个分类阶段预热 5 秒、采样 10 秒、间隔 5 秒，共 3 点，随后读取同一 coalition 内全部 WebContent 的 `vmmap -summary`。**这是带阶段诊断的单次试验，不能当作普通模式性能基准或精确收益估计。** 基线有额外中间分类，候选只读取初始与最终分类，操作间隔也不同。

原版主窗口 PID 77734，候选 PID 80133，分别在各自阶段保持相同 PID / 启动身份。初始只有 Main / Stack 两个 WebContent，首次快速添加后增加共用弹窗 WebContent，最终均为 3 个 WebContent / 6 个总进程。主窗口通过本场景唯一的大图形资源持有进程推断，仍未获得原生 page / PID 直接映射。

两版均完成设置往返 4 次、主窗口隐藏再重开、20 次空标题快速添加 / Escape 取消，应用日志完整记录 20 次打开与成功焦点恢复。基线第一次打开时日志尚未写入，自动化读数检查提前报错；随后等待打开记录再取消，没有重复打开。该时间差保留在证据中，不能视为严格等时对照。

设置往返和单独重开没有复现明显增长。原版增长发生在“第二轮操作 + 最终隐藏”这段流程：第二轮操作与隐藏之间没有单独分类，因此不能认定隐藏是唯一触发因素，更不能认定某个具体图层泄漏。候选增加内部滚动区域后图形占用更高，与额外绘制表面的假设相符，但本轮没有读取 Web Inspector 图层树，具体图层归属仍未确认。

WebKit 的 Layers 工具可以显示图层尺寸、创建原因及内存成本。下一项定位应读取实际图层树再选择修改，不重复固定视口容器、隐藏视口缩小或窗口销毁试验。参考 [WebKit Layers 文档](https://webkit.org/web-inspector/layers-tab/)。
