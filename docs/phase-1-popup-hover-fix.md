# 快速卡片悬停交接修复 · 构建 19

2026-10-07。修复 macOS 共用弹窗下，鼠标从桌面标签进入快速卡片后仍触发关闭计时的问题。

## 原因与修改

构建 14 将快速卡片 / 快速添加共用的物理窗口命名为 `popup`，原 `QuickSession` 仍只接受名为 `quick` 的卡片进入事件。另一方面，共用弹窗的消息校验要求前端携带视图和代次，原生鼠标回调没有这些前端字段，因此其进入事件也被丢弃。标签离开后，进入卡片不能取消原定的 500ms 关闭计时。

- 悬停会话在开启时记录来源窗口和卡片的实际窗口名称，不再写死 `quick`；Windows 独立卡片继续记录其原名称。
- 原生回调带上不可从 JSON 解码的内部标记，允许自身鼠标位置通知通过。前端消息仍须携带当前视图和代次，旧卡片的 presence、关闭、操作等消息继续被拦截。
- 关闭时清理实际卡片窗口的悬停记录。停留在标签或卡片中保留会话，离开两者 500ms 后收起，重新进入取消待关闭计时。

## 验证

- 新增的原生消息校验回归测试在修复前失败，修复后通过；同时验证 renderer JSON 无法伪造原生标记，旧卡片消息不能影响替换后的快速添加。
- 共用 `popup` 窗口的跨间隙进入、旧计时失效、离开后关闭及重新进入测试通过；原 `quick` 窗口和加载 / 编辑状态测试继续通过。
- 前端 21 项测试、Svelte 0 错误 / 0 警告、macOS 打包必需的 Go 模块 / 控制器 / 集成测试与 vet、签名和 DMG 校验通过。
- Windows amd64 / arm64 生产模式交叉编译通过；未宣称完成 Windows 实机悬停验收。
- 独立 macOS 实例退出整理后处于被动状态，日志记录共用卡片 `activeInput=false`，接收到原生 `popup inside=true`，其中一段进入至离开间隔为 **4.772614 秒**，超过原 500ms 截止时间。期间 Computer Use 报告外部输入变化，随后重新读取了状态，因此该日志作为原生进入与保持的证据，不当作完全受控的连续鼠标轨迹验收。
- 快速添加打开、Escape 取消、返回任务主窗口通过。受限启动曾返回 Launch Services 错误，使用允许访问自身测试应用的启动方式后恢复；不属于产品启动失败。
