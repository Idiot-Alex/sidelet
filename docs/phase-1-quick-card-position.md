# 卡片编辑后的定位

日期：2026-10-07。macOS 本地预览构建 22。

## 问题与修复

点击“编辑 → 取消”后，阅读卡片会向下移动。原生缩放逻辑为避免鼠标在卡片变矮时落到窗口外，会调整位置以保留编辑器底部的点击位置。构建 21 已让编辑结束后的卡片保持键盘操作状态，不再因鼠标离开自动关闭，因此这段鼠标保护反而造成了位置跳动。

macOS 与 Windows 的定位逻辑现只对被动卡片保留鼠标；编辑与键盘操作中的卡片使用原任务锚点和工作区边界计算位置。取消后内容不变时恢复原来的阅读位置；保存后按新内容高度定位。靠近屏幕底部时，编辑器仍会按高度上移以避开边界，取消后恢复阅读位置。

## 验证

- 新增原生回归用例：鼠标留在编辑器底部时，活动卡片缩小仍使用任务锚点。修复前该用例失败，修复后原生 49 项全部通过；被动卡片保留鼠标的原用例继续通过。
- 隔离内存任务实例的真实窗口点击：短卡片连续取消两次、保存一次，位置始终为 `x=1104, y=176, width=320, height=182`。
- 底部卡片真实点击：阅读窗口为 `x=1383, y=677, width=320, height=208`，编辑器受工作区约束上移到 `y=640, height=390`，取消后完整恢复到原阅读矩形。界面返回阅读，标题和备注保留。
